Quadrix OS 1_0700_261026

### Многоядерность

- Потоки одной программы выполняются на разных ядрах одновременно
  (раньше — все на одном): ядро сбрасывает TLB на других процессорах при
  изменении памяти программы, простаивающий процессор забирает готовые
  потоки у занятых. Счётная программа на 4 ядрах — в 3,7 раза быстрее.
- Ожидание потоков и событий в программах Windows — по уведомлению, а не
  опросом каждые 5 мс: переключение потоков в 10 раз быстрее.

### Терминал

- Новый терминал: оболочка в стиле PowerShell — переменные, конвейеры
  объектов, `if`/`foreach`/`while`/`switch`/`try`, функции, сценарии
  `.ps1`, операторы `-eq -like -match -replace -split`, форматирование
  таблицами и списками. Команды cmd и Linux работают как псевдонимы (`dir`,
  `ls`, `type`, `cat`, `del`, `rm`, `ps`, `kill`, `grep`…).
- Консольные программы Linux, Windows (`.exe`), Python и Quadrix
  запускаются в окне терминала: ввод с клавиатуры, Ctrl+C, цвета ANSI,
  вывод в конвейер и переменные.
- Вкладки, выделение мышью и копирование, вставка, дополнение по Tab,
  история команд.
- Системные команды: процессы, службы, диски, устройства, сеть, пакеты
  Linux, питание, язык и часовой пояс.

### Программы Windows

- Встроенная среда Visual C++ (замена Visual C++ Redistributable):
  vcruntime140, ucrtbase и api-ms-win-crt-* — запуск программ UCRT
  (`__p___argc`, `_configure_narrow_argv`…), `__stdio_common_*`,
  безопасные функции `*_s`, потоки `_beginthreadex`, `std::exception` и
  `type_info`. Программы, собранные современными Visual Studio и MinGW
  (UCRT), запускаются.
- Настоящие DLL рядом с программой (zlib1.dll, SDL2.dll и т. п.):
  загрузка, импорт и экспорт с переадресацией, `DllMain`, TLS,
  `LoadLibrary`/`GetProcAddress`.
- Окно ошибки при сбое программы: код исключения, адрес в модуле,
  регистры и вызванные неподдерживаемые функции; окно при `abort()`,
  необработанном исключении C++ и нехватке DLL при запуске.
- `CreateProcess`, `StretchDIBits`, `SetDIBitsToDevice`, `GdiFlush`; `qsort`
  стал быстрым (пирамидальная сортировка).
- Python для Windows (встраиваемый python.org, 3.12) работает: модули,
  файлы, потоки, `time.sleep`, `input()`. Для этого добавлены семафоры,
  мьютексы, ожидающие таймеры, сведения о файлах, отображение файлов,
  ввод-вывод по номерам файлов (`_open`/`_read`/`_write`), `_wstat`,
  `conio`, `_wspawnv`, математика C99, `FormatMessage` с выделением
  буфера, пустой реестр (значения по умолчанию).

### Тесты производительности

- `qxbench` (в `~/Windows` и `~/Linux`, исходник `data/bench/qxbench.c`):
  процессор и память, диск и файлы, потоки и процессы, графика окон.
  Тот же `qxbench.exe` запускается на Windows; `qxbench --compare
  qxbench-windows.txt qxbench-quadrix.txt` сравнивает результаты.

### Хранилище и установка

- Запись на диск в отдельном потоке: служба файлов отвечает программам
  сразу, данные уходят на диск в фоне (порядок записей и барьеров
  сохраняется). Система не замирает при установке пакетов и копировании.
- Контроллер IDE (VirtualBox «PIIX4», QEMU): обмен по DMA вместо побайтного
  чтения портов — установка системы и пакетов на таком диске в 2–2,5 раза
  быстрее.
- «Код»: загрузка компиляторов и сборка не подвешивают систему.
- Программы в образе — без таблиц символов (образ меньше на 5 МБ):
  обновление снова помещается в загрузочный раздел 128 МиБ прежних
  установок; у новых установок раздел — 256 МиБ, с запасом.

### Рабочий стол

- Нет следов окна после разворачивания и восстановления кнопкой и после
  смены темы; анимация сворачивания не оставляет полос по краям.

Обновление ставится из «Настройки → Обновление»; образ ISO — для новой установки.
